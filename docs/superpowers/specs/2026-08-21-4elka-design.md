# 4elka — дизайн

**Дата:** 2026-08-21
**Статус:** на ревью у автора

Личное приложение для macOS: челка MacBook становится местом, где живут буфер обмена,
скриншоты, полка файлов, плеер, календарь, заряд устройств и погода.

---

## 1. Зачем

Три вещи, которые делаются каждый день и сейчас делаются неудобно:

1. **Скриншоты.** Снимаются через `cmd+shift+ctrl+3/4`, то есть уже ложатся в буфер обмена,
   а не на десктоп. Но буфер один — предыдущий скриншот теряется. Нужен стек последних,
   из которого можно вытащить один или сразу несколько.
2. **Буфер обмена.** То же самое для обычного `cmd+c`: истории нет, перезатёрлось — потерялось.
3. **Музыка.** Играет почти всегда из Яндекс Музыки. Переключать и видеть, что играет,
   не переключаясь в приложение.

Плюс мелкие постоянные вопросы: какое сегодня число и когда выходные, сколько осталось
в наушниках, сколько на улице градусов.

## 2. Скоуп

### Делаем

| Блок | Что именно |
|---|---|
| Буфер обмена | История с поиском. Текст, картинки, файлы. Пины (не вытесняются). |
| Скриншоты | Стек последних картинок отдельной вкладкой. Вытаскивание одного и пачкой. |
| Полка файлов | Кинул файл на челку — полежал. Забрал перетаскиванием или отправил по AirDrop. |
| Музыка | Карточка с обложкой, названием и исполнителем **выезжает из-под челки на каждое событие**: смена трека, пауза, снятие с паузы. Кнопки: назад / пауза-плей / вперёд. |
| Календарь | Сетка месяца: дни недели, выходные другим цветом, сегодня выделено, переключение месяцев. **Без событий и напоминаний.** |
| Заряд устройств | Мак, наушники, BT-мышь и клавиатура. Айфон — **только пока воткнут кабель** (см. §8). |
| Уведомления о заряде | Карточка выезжает из челки, когда заряд любого устройства упал ниже нижнего порога или дозарядился до верхнего. Срабатывает **на пересечении**, не на каждом опросе. |
| Подтверждение попадания в буфер | Снял скриншот, скопировал текст или файлы — карточка выехала с превью того, что попало. Работает для всех трёх типов. |
| Погода | Текущая температура и ощущается-как для Астаны. |
| Иконка в строке меню | Единственный способ выключить приложение, открыть настройки и понять, что оно вообще запущено. Как у ProxyPilot: иконка справа в строке меню, меню с пунктами. |

Действия над элементом буфера (решено в §12 — берём все): распознать текст с картинки,
вставить без форматирования, преобразовать (JSON, base64, URL, JWT, время из числа в дату).

### Сознательно не делаем

- **Последовательная вставка** — выигрыш мелкий, а требует разрешения на управление
  компьютером, из-за которого всё остальное перестало бы работать «из коробки».
- **Индикатор долгих команд / прогресс в челке** — не нужно.
- **Локальный LLM** (`FoundationModels`). Замерено: фреймворк на машине есть, но состояние
  `appleIntelligenceNotEnabled`, и главное — **русского нет** среди 23 поддерживаемых языков,
  а контент в основном русский. Не бэклог, а отказ.
- **Заряд айфона по воздуху** — публичного способа получить его с мака нет. По кабелю
  делаем, см. §8.
- Помодоро, замена системных HUD, зеркало, оконный менеджер, события календаря.

**Ключевой вывод, определяющий весь проект:** macOS сама кладёт скриншот в буфер обмена,
поэтому мы **ничего не перехватываем**. Следим за буфером — и всё. Отсюда: нет конфликтов
с системными хоткеями, **не нужно разрешение на запись экрана**, и «стек скриншотов»
с «историей `cmd+c`» — это один движок, а не два.

**Второй вывод:** геометрия челки считается публичным API точно, поэтому библиотеку
`DynamicNotchKit` не берём. Она не документирует перетаскивание **изнутри** своего окна,
а это ровно наш главный жест. Своё окно — примерно 150 строк и полный контроль.

## 4. Архитектура

Одно приложение без иконки в доке (`LSUIElement`), одно окно над челкой, семь независимых
поставщиков данных. Поставщики ничего не знают друг о друге и о вьюхах.

```
Sources/Chelka/
  App/         точка входа, делегат приложения, корневой стор состояния
  Notch/       окно над челкой, зона-триггер, геометрия, состояния
  Clipboard/   наблюдатель буфера, стор истории, правила игнора, блобы, индекс
  Shelf/       полка файлов, AirDrop
  Activity/    общая выезжающая карточка: очередь, показ, автоскрытие
  Media/       мост к MediaRemote, состояние плеера
  Month/       сетка месяца
  Devices/     заряд устройств
  Weather/     клиент Open-Meteo, кэш
  Actions/     действия над элементом: OCR, преобразования
  Core/        Config, общие типы, атомарная запись файлов
  UI/          вьюхи (тонкие, без логики)
```

> **Грабля с именем.** Имя модуля Swift не может начинаться с цифры, поэтому модуль
> называется `Chelka`, а продукт и бандл — `4elka.app`. Идентификатор бандла
> `com.adylenya.4elka` валиден, с цифры начинаться можно.

### Границы модулей

Каждый поставщик данных — это «чистое состояние + способ его обновить»:

```swift
protocol StateSource {
    associatedtype State: Equatable
    var state: State { get }          // иммутабельный снимок
}
```

Вьюха подписывается на снимок и перерисовывается. Логика обновления живёт в поставщике,
и она тестируется без UI. Обратное направление (действия) — отдельные методы, а не мутация
состояния снаружи.

### Иммутабельность

Ни один тип состояния не имеет мутирующих методов. Изменение = новый экземпляр:

```swift
struct HistoryStore {
    let items: [ClipItem]
    func inserting(_ item: ClipItem, limits: Limits) -> HistoryStore
    func pinning(_ id: ClipItem.ID) -> HistoryStore
    func removing(_ id: ClipItem.ID) -> HistoryStore
}
```

## 5. Буфер обмена

### Модель

```swift
struct ClipItem: Identifiable, Equatable {
    let id: UUID
    let kind: Kind
    let sourceApp: SourceApp?     // для подписи «из Chrome», не для логики
    let createdAt: Date
    let contentHash: String       // SHA-256 полезной нагрузки
    let isPinned: Bool

    enum Kind: Equatable {
        case text(String)
        case image(ImageRef)      // блоб на диске + размер + формат
        case files([URL])
    }
}
```

### Как ловим

Уведомлений об изменении буфера в macOS нет, поэтому опрос `NSPasteboard.general.changeCount`
раз в 200 мс на фоновой очереди. Изменился — читаем типы, собираем `ClipItem`, кладём в стор.

### Правила игнора — требование безопасности, не настройка

Пропускаем запись, если:

- на буфере есть `org.nspasteboard.ConcealedType`, `TransientType` или `AutoGeneratedType` —
  так менеджеры паролей просят их не сохранять. **Без этого мы будем складывать пароли в историю.**
- источник в блоклисте (менеджеры паролей, связка ключей);
- источник — мы сами. Иначе клик по элементу («положить в буфер») породит новую запись,
  и получится бесконечный цикл;
- размер картинки больше потолка из `Config`.

### Вытеснение

Раздельные квоты по типу, потому что картинки тяжёлые: текст 200, картинки 30, файлы 50.
Закреплённые не вытесняются никогда. Числа — в `Config`, не в коде.

Дедупликация по `contentHash`: повторное копирование того же поднимает существующий элемент
наверх, а не создаёт второй.

### Хранение

- Блобы — файлами в `~/Library/Application Support/4elka/blobs/<uuid>.<ext>`.
  Пишутся один раз, никогда не меняются, удаляются при вытеснении.
- Индекс — `index.json`, атомарная замена (запись во временный файл + `replaceItem`),
  дебаунс 1 секунда.
- На старте элементы с пропавшим блобом молча отбрасываются — стор самолечится.

SQLite сознательно не берём: на 280 элементов JSON быстрее любого кадра отрисовки
и тянет ноль зависимостей.

### Скриншоты: честное ограничение

Надёжно отличить скриншот от «скопировал картинку в браузере» через `NSPasteboard` нельзя —
источник там не гарантирован. Поэтому вкладка «Скриншоты» показывает **просто картинки**,
без эвристик. На практике картинки в буфере почти всегда и есть скриншоты, а угадайка
по размерам и формату дала бы баги на ровном месте. Приложение-источник всё равно храним —
для подписи, но не для классификации.

### Вытаскивание наружу

Мультивыбор: `cmd`-клик добавляет к выделению, `shift`-клик — диапазон.
Перетаскивание отдаёт `NSFilePromiseProvider` (для картинок и файлов, в том числе несколько
за раз) либо строку (для текста). Файлы для перетаскивания материализуются в temp-каталог
лениво — в момент, когда принимающая сторона запросит содержимое.

## 6. Окно над челкой

Один `NSPanel`:

- `.nonactivatingPanel` — **критично**. Иначе панель забирает фокус, и `cmd+V` после клика
  по элементу уйдёт в неё, а не в приложение, куда ты вставляешь. Это ломало бы весь смысл.
- уровень выше меню-бара, `collectionBehavior = [.canJoinAllSpaces, .stationary, .fullScreenAuxiliary]`;
- прозрачный фон, скругления рисуем сами.

Геометрия из `NSScreen`: `safeAreaInsets.top` даёт высоту (38), а
`auxiliaryTopLeftArea.maxX` и `auxiliaryTopRightArea.minX` — границы челки (ширина 220,
центр 1028). Пересчитывается на смену экрана и разрешения.

**На экране без челки** (внешний монитор, закрытая крышка) `auxiliaryTopLeftArea` равен `nil`.
Тогда панель работает как плашка по центру верхнего края, а зона-триггер получает
ширину челки по умолчанию из `Config`. Приложение не должно молча перестать работать
при подключении монитора.

Отдельная невидимая **зона-триггер** ровно по прямоугольнику челки ловит наведение и клик,
когда панель скрыта.

### Челка — часть интерфейса, а не место для текста

Замечено владельцем на живом приложении 21.08: панель ставилась так, что её верхний
край совпадал с верхом экрана, и верхние 38 точек физически прятались за челкой.
Всё нарисованное там было не видно.

Поэтому челка считается **непрозрачным препятствием**, и раскладка обходит его:

- **Полоса рядом с челкой.** В верхних 38 точках доступны только два прямоугольника —
  слева и справа от челки. Там место коротким вещам: время, погода, заряд.
- **Тело панели** — всё, что ниже челки. Там основное: сетка истории, плеер, календарь.
- **Выезжающая карточка начинается ПОД челкой**, а не из-под её верхнего края.
  Иначе первая строка карточки съедается.

Расчёт этих трёх прямоугольников — чистая функция `NotchLayout`, потому что именно её
и надо проверять тестом, а не глазами.

### Фокус: панель забирает клавиатуру только раскрытой

Замечено владельцем там же: карточка уведомления перехватывала набор текста —
человек печатал, карточка выезжала, и нажатия уходили в неё.

Причина была в том, что окну разрешалось становиться клавиатурным **всегда**.
Разрешение нужно ровно в одном состоянии — раскрытом, где есть поле поиска.
Во всех остальных панель обязана быть неспособна принять фокус.

Проверка: печатать в редакторе, пока выезжают карточки. Ни один символ не должен
пропасть.

### Состояния

| Состояние | Когда | Что видно |
|---|---|---|
| `hidden` | по умолчанию | ничего, челка остаётся челкой |
| `peek` | наведение | тонкая подсказка |
| `activity` | событие плеера | карточка трека, уезжает сама |
| `expanded` | клик по челке или хоткей | панель ~640×340 |

В раскрытом виде: слева плеер, справа сетка с вкладками «Буфер / Скриншоты / Полка»,
внизу узкая полоса — календарь, заряды, погода.

Взаимодействие: клик = положить в буфер и закрыть, `cmd`-клик = выделить,
перетаскивание = вытащить, `⌫` = удалить, `⌘P` = закрепить, `Esc` = закрыть,
ввод текста = поиск.

## 7. Музыка

`MediaRemoteBridge` держит **один долгоживущий** процесс
`/usr/bin/perl mediaremote-adapter.pl <framework> stream`, читает stdout построчно вне
главного потока и разбирает каждую строку как JSON.

Поток отдаёт **диффы**, поэтому состояние собирается чистой функцией:

```swift
func applying(_ diff: NowPlayingDiff) -> NowPlaying
```

Она тестируется на **настоящем логе потока, снятом с целевой машины** — фикстура уже есть.

Живая позиция считается как `elapsedTime + (now − timestamp)`, пока `playing == true`,
иначе просто `elapsedTime`. Это объясняет наблюдение из замеров: разовый запрос `get`
отдаёт не текущую позицию, а опорную точку со временем.

Команды — короткоживущие вызовы того же скрипта с числовым кодом
(0 плей, 1 пауза, 2 переключить, 4 вперёд, 5 назад).

Обложка приходит внутри потока как base64 JPEG. Декодируем один раз и кэшируем
по паре «название + исполнитель» (не по `contentItemIdentifier` — см. выше), иначе будем
декодировать картинку на каждом обновлении позиции.

Поток различает полные снимки и частичные: у строки есть флаг `diff`. При `diff = false`
состояние заменяется целиком, при `diff = true` — сливается поверх. Пустой полный снимок
означает «ничего не играет».

### Выезжающая карточка — общая поверхность

Карточка не принадлежит плееру. Это общий канал уведомлений `Activity`, в который пишут
и плеер, и батареи, и что угодно потом. У него одна очередь и одно правило показа:

- карточка живёт `Config.activityDuration` (по умолчанию 3 с) и уезжает;
- пришло новое событие, пока карточка на экране — таймер перезапускается, а не плодится
  вторая карточка;
- пока панель раскрыта, карточки подавляются: там всё и так видно;
- события приоритизированы: критический заряд важнее попадания в буфер, попадание в буфер
  важнее смены трека.

Поставщиков три:

1. **Плеер** — сменилась пара «название + исполнитель» либо изменился `playing`.

   ⚠️ **Не по `contentItemIdentifier`.** Замер на фикстуре показал, что он меняется
   при каждом обновлении состояния, а не при смене трека: за один «Sunflower» он сменился
   трижды. Опознавание трека по нему заставило бы карточку выскакивать каждые несколько
   секунд. Идентичность трека — это название плюс исполнитель.
2. **Батареи** — пересечён порог (см. ниже).
3. **Буфер** — в историю добавился элемент. Карточка показывает, что именно попало:
   миниатюру для картинки, первую строку для текста, имена для файлов. Это подтверждение
   в первую очередь для скриншотов: раньше единственным признаком удачи был звук затвора.

Приятное следствие правил игнора: когда мы сами кладём элемент в буфер по клику
пользователя, запись отсекается как «от нас самих» — и карточка не выезжает. Эха нет,
отдельного флага для этого не потребовалось.

Копирование текста происходит часто, поэтому у каждого из трёх поставщиков есть
свой выключатель в `Config`. По умолчанию включены все.

### Живучесть

Процесс умер — переподнимаем с растущей задержкой. Команда `test` адаптера провалилась
(Apple закрутила гайки в будущей macOS) — секция плеера честно скрывается, а не показывает
вранье. Вся механика спрятана за протоколом `MediaSource`, так что замена реализации
не потребует трогать UI.

**Побочная выгода:** источник — системный Now Playing, а не Яндекс. Значит YouTube в Chrome,
Apple Music и что угодно ещё поедут бесплатно, без единой строчки под них.

## 8. Календарь, заряды, погода

### Календарь

Чистая функция без побочных эффектов и без данных извне:

```swift
struct MonthGrid { let weeks: [[Day?]] }
func makeMonthGrid(year: Int, month: Int, calendar: Calendar) -> MonthGrid
```

Выходные определяются из `calendar`, а не хардкодом по индексу — иначе сломается при смене
первого дня недели. Сегодняшний день выделен. Стрелки переключают месяц, открытие панели
всегда возвращает на текущий.

### Заряды

`system_profiler SPBluetoothDataType -json` для наушников, мыши и клавиатуры плюс
`pmset`/IOKit для мака. `system_profiler` медленный (1–2 с), поэтому опрос раз в 60 с
в фоне с кэшированием. Наушники отдают левое и правое ухо отдельно — показываем минимум
из двух, чтобы не соврать в плюс.

**Айфон — только по кабелю.** Замерено: телефон, подключённый по USB, отдаёт заряд через
`usbmuxd` — тот же канал, которым пользуется Finder. Беспроводного пути нет: по блютусу
телефон заряд не рапортует, а из iCloud его наружу не отдают. Значит строка с айфоном
появляется, когда кабель воткнут, и исчезает, когда вынут. Это не деградация, а честное
поведение: полезно оно ровно во включённом состоянии — видно, когда дозарядился до сотни.

Читаем через `ideviceinfo` из `libimobiledevice`. **Жёсткой зависимости нет:** нет утилиты —
строка айфона просто не показывается, остальное работает. Не тащим приватный
`MobileDevice.framework`: он недокументирован и Apple ломает его молча.

### Уведомления о заряде

Правило — чистая функция от прошлого и нового состояния, возвращающая список событий:

```swift
func alerts(from old: [DeviceCharge], to new: [DeviceCharge],
            thresholds: Thresholds) -> [BatteryAlert]
```

Срабатывание **только на пересечении порога**, иначе на 19% челка выезжала бы каждую минуту
до конца времён. Поэтому у каждого устройства есть взведённое состояние, и оно
перевзводится с гистерезисом:

- упал ниже `low` (по умолчанию 20%) → карточка «мало»; повторно только после того,
  как поднялся выше `low + hysteresis`;
- заряжается и поднялся выше `high` (по умолчанию 80%) → карточка «уже много, можно
  отключать»; повторно только после того, как упал ниже `high − hysteresis`;
- дозарядился до 100% → отдельная карточка.

Гистерезис по умолчанию 5 процентных пунктов. Все числа — в `Config`.
Устройство исчезло из списка (вынули кабель, выключили наушники) — его взведённое
состояние забывается, чтобы при следующем подключении правило отработало заново.

### Погода

Open-Meteo, без ключа и без разрешения на геолокацию: координаты Астаны лежат в `Config`.
Обновление раз в 15 минут, ответ проверяется схемой и диапазонами (температура в разумных
пределах — внешним данным не доверяем), последнее удачное значение кэшируется на диск.
Сети нет — показываем кэш с отметкой, когда он получен, а не пустоту и не ноль.

## 8а. Внешний вид

Родная тема macOS 26 на Liquid Glass, **без единого своего цвета и без своего
переключателя тем**.

### Стекло

Замерено на целевой машине: в SDK от Command Line Tools есть `NSGlassEffectView`
(macOS 26) со свойствами `style` (`.regular` / `.clear`), `cornerRadius`, `tintColor`,
и `NSGlassEffectContainerView` со `spacing`, который сливает соседние стеклянные
элементы в один и экономит проходы отрисовки.

⚠️ **SwiftUI-модификатора `.glassEffect()` в этом SDK нет.** Есть только стиль кнопок
`.buttonStyle(.glass)` (`GlassButtonStyle`). Поэтому стекло берётся из AppKit:
одна обёртка `UI/GlassPanel.swift` (`NSViewRepresentable` вокруг `NSGlassEffectView`),
через которую рисуются панель и выезжающая карточка. Кнопки плеера — `.glass`.

Стеклянные элементы, стоящие рядом (кнопки плеера, плитки), заворачиваются
в `NSGlassEffectContainerView`, иначе каждый считается отдельным проходом.

### Тема

Тема **системная и только системная**. Приложение не имеет своей палитры и своего
тумблера: используются исключительно семантические цвета (`NSColor.labelColor`,
`.secondaryLabelColor`, `.tertiaryLabelColor`, `.controlAccentColor`,
`.separatorColor`) и стеклянные материалы.

Из этого бесплатно получается всё, что нужно: переключил тему в системных настройках —
переключилась и у нас; стоит режим «Авто», который сам меняет светлую на тёмную
по времени суток — меняется и у нас. Своего кода для этого не пишется вообще,
и именно поэтому не может рассинхронизироваться.

**Запрещено:** хардкод цветов (`NSColor(red:...)`, `Color(hex:)`), собственные
светлая и тёмная палитры, чтение времени суток для выбора темы, любой пользовательский
переключатель темы. Проверка на ревью: поиск по `NSColor(` и `Color(` не должен
находить ничего, кроме семантических имён.

### Следствие для платформы

Нижняя граница поднята до **macOS 26** (и `swift-tools-version:6.2`, потому что
`.macOS(.v26)` появился только в PackageDescription 6.2). Это убирает `if #available`
вокруг каждого стеклянного элемента. Приложение личное и работает на одной машине
с macOS 26.5.1, так что терять совместимость не с кем.

## 8б. Иконка в строке меню

Приложение живёт без иконки в доке, а панель появляется только над челкой. Значит без
иконки в строке меню у него **нет ни одного способа быть выключенным** — и человек,
случайно его запустивший, остаётся с панелью, которую нечем закрыть. Это ровно то, что
произошло на живой машине 21.08 и почему пункт появился.

`NSStatusItem` справа в строке меню, иконка — системный символ. Меню:

- **Показать панель** — то же, что клик по челке;
- **Настройки…** — окно с тумблерами того, что уже есть в `Config`: пороги заряда,
  город погоды, время жизни карточки, какие поставщики карточек включены;
- **Автозапуск при входе** — тумблер;
- **Выключить 4elka** — и приложение действительно завершается.

Иконка обязательна и выключаться не может: она и есть аварийный выход.

## 9. Разрешения: ни одного

Полный список того, чего приложению **не** нужно: запись экрана, управление компьютером,
геолокация, календарь, полный доступ к диску, микрофон, уведомления.

Это следствие дизайна, а не удача: скриншоты берём из буфера, а не снимаем сами;
календарь считаем, а не читаем; погоду берём по фиксированным координатам;
вставку в чужое окно не эмулируем.

Одна оговорка для честности: чтение заряда айфона требует, чтобы телефон был **доверенным
устройством** для этого мака. Это не разрешение macOS, а разовое «Доверять?» на самом
телефоне, и на целевой машине оно уже выдано.

## 10. Сборка

SwiftPM без Xcode — SDK от Command Line Tools версии 26.5 достаточно, проверено сборкой
фреймворка адаптера тем же способом.

`Makefile`:

- `make adapter` — собирает `MediaRemoteAdapter.framework` из исходников одной командой
  `clang` (проверено на целевой машине). В репозиторий кладём скрипт сборки, не бинарник.
- `make app` — релизная сборка, сборка бандла `4elka.app`: `Info.plist` с `LSUIElement`,
  копирование ресурсных бандлов SwiftPM, фреймворка адаптера и perl-скрипта, подпись.
- `make dev` — собрать и перезапустить.
- `make test` — тесты.

Подпись — постоянным самоподписанным сертификатом, а не разовой ad-hoc: иначе подпись
меняется на каждой сборке. Для v1 без разрешений это не критично, но правильно сразу.

Зависимостей кода — **ноль**. Глобальный хоткей делается через Carbon
`RegisterEventHotKey`: это единственный способ поймать комбинацию без разрешения
на управление компьютером, и ради одного хоткея тащить библиотеку незачем.
Адаптер MediaRemote не зависимость, а вендоренный ресурс, собираемый из исходников.

Внешняя необязательная: `ideviceinfo` из `libimobiledevice` (brew) для заряда айфона.
Нет её — строка айфона не показывается, всё остальное работает.

## 11. Тестирование

Логика вынесена из вьюх именно затем, чтобы её можно было проверить. Тестами покрываем:

| Юнит | Что проверяем |

| `HistoryStore` | иммутабельность (исходный снимок не меняется), вытеснение по квотам, пины не вытесняются, дедуп поднимает наверх |
| `IgnoreRules` | все три служебных типа, блоклист, собственный источник, потолок размера |
| `NowPlaying.applying` | накопление диффов на **реальном логе потока**, вычисление живой позиции, смена трека |
| `makeMonthGrid` | границы месяцев, февраль в високосный год, первый день недели, выходные |

| `WeatherResponse` | разбор, отказ на мусоре, отказ на температуре вне диапазона |

| `BatteryAlerts` | срабатывание на пересечении, отсутствие повторов при удержании ниже порога, перевзведение с гистерезисом, забывание исчезнувшего устройства, порог «много» только при зарядке |

Порядок работы по каждому пункту: сначала падающий тест, потом реализация.

## 12. Решённое по ходу

**Действия над элементом буфера — берём все три.** Прозвучавшее «буфера достаточно»
относилось к отказу от последовательной вставки, а не к этим действиям: они не меняют
жест вставки, а добавляют пункты в меню элемента. Все три дешёвые, все три — чистые
функции в отдельном модуле `Actions/`, любую можно вычеркнуть потом без последствий:

- распознать текст с картинки (`ru-RU` подтверждён замером),
- вставить без форматирования,
- преобразовать: JSON красиво / в строку, base64, URL, разбор JWT, время из числа в дату.

**Заряд айфона — берём, с честным ограничением.** Только пока воткнут кабель, см. §8.
