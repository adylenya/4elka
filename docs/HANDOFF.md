## Правила, выведенные болью

Это не стиль, а вещи, на которых уже спотыкались. Каждая стоила времени.

**Тесты запускать только через `./scripts/test.sh`.** В Command Line Tools нет модуля
`XCTest`, а `Testing.framework` есть, но SwiftPM не знает путей до него. Обвязка их
подставляет. Обход через `unsafeFlags` однажды дал **ложно-зелёный результат**: сборка
проходила, тестов запускалось ноль, код выхода был нулевой.

**Предупреждения мерить только так:** `rm -rf .build && ./scripts/test.sh 2>&1 | grep -c "warning:"`.
Обычный `swift build` собирает лишь исходники и тестовый таргет не видит — на этом
полсессии докладывалось неверное «ноль». Повторный запуск без чистки тоже врёт:
перекомпилировать нечего.

**Код выхода мерить без конвейера.** `./scripts/test.sh | tail` возвращает код `tail`,
а не тестов.

**Ручного обещания `Sendable` не давать.** В этом проекте оно дважды скрывало настоящие
гонки, и оба раза вскрывалось только когда ревьюер проходил по каждому полю отдельно.
Правильный ответ — изоляция актором.

**Константы из `Config` в задание не попадают.** Генератор заданий вырезает только раздел
своей задачи. Добавляя константу, значение надо продублировать в текст задачи — иначе
исполнитель придумает своё, и план с кодом разойдутся молча. Попались дважды.

**Фикстуры, снятые с живой машины, чистить до публикации — и историю тоже.** В дампе
`system_profiler` лежали серийники наушников владельца, блютус-адреса устройств и мака,
и чужое устройство постороннего человека. Чистка рабочего файла не помогает: старая версия
остаётся в коммите.

**Работа исполнителей — только в отдельных воркри.** Двое агентов в общем дереве
привели к тому, что несохранённые правки одного молча откатились.

**Гасить приложение только по имени исполняемого файла.** Шаблон `pkill -f "4elka.*/Chelka"`
совпадает и с процессами компилятора — уже убивал сборку соседнего агента.

**Автозапуск при входе не включать на проверках.** Регистрация проходит даже из воркри
и создаёт настоящий элемент входа, указывающий на одноразовую сборку.

## Как продолжать

1. **Журнал** — `.superpowers/sdd/2026-08-21-4elka/progress.md`. Там вся история решений,
   включая отклонённые варианты и причины. Читать его, а не восстанавливать по коду.
2. **План** — `docs/superpowers/plans/2026-08-21-4elka.md`, 29 задач с кодом и тестами.
   **Спека** — `docs/superpowers/specs/2026-08-21-4elka-design.md`, там же таблица замеров
   с живой машины: что проверено и чем.
3. **Задание для агента** нарезается скриптом:
   `bash <skill>/scripts/task-brief docs/superpowers/plans/2026-08-21-4elka.md <номер>`
4. **Пакет для ревью** — `scripts/review-package <план> <база> <верхушка>`. База это точка
   ветвления воркри (`git merge-base`), а не текущая верхушка `main`: иначе в дифф попадут
   чужие коммиты и ревьюер найдёт «загрязнение», которого нет. На этом уже спотыкались.
5. **После каждого мержа** сверять константы плана и кода — расхождение не ловится ни
   ревью диффа, ни отчётом исполнителя.
