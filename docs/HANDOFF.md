## Что нашли ревью (четыре штуки, три закончены)

Ревьюили **по текущему состоянию `main`, а не по диффам**: историю писали двадцать с
лишним агентов, она переплетена, и код с тех пор уехал. Разбито по подсистемам.

**Буфер обмена — четыре критичных.** Битый файл индекса молча стирает всю историю и
тут же перезаписывается пустым (проверено: 50 записей → 0, файл с 8480 байт до 216).
Файл картинки удаляется раньше, чем индекс перестал на него ссылаться, из-за чего
закреплённая картинка исчезает целиком. Нет сброса на диск при выходе: удалил из
истории пароль, вышел — он вернулся. `⌫` удаляет невидимое выделение с другой
вкладки. Плюс осиротевшие файлы не собираются никогда.

**Окна — три критичных**, см. выше. Задача 31.

**Плеер и жест — один критичный:** обработчик завершения старого процесса гасит уже
запущенный новый, и пять таких пар подряд выключают плеер до перезапуска
приложения. Дефект дремлет, потому что `stop()` не зовёт никто — сработает ровно в
момент подключения плеера к панели. Плюс: буфер строк не сбрасывается при
перезапуске потока (после обрыва панель уверенно показывает прошлый трек), одна
слишком длинная строка выбрасывает соседнюю здоровую, поток ошибок адаптера
отправлен в никуда — то есть самый вероятный сбой не диагностируется.

**Четвёртое ревью** (погода, календарь, заряды, действия над текстом, ядро, хоткей,
полка) — в работе. Эти подсистемы до сих пор не смотрел никто.

## Правила, выведенные болью

Это не стиль, а вещи, на которых уже спотыкались. Каждая стоила времени.

**Тесты запускать только через `./scripts/test.sh`.** В Command Line Tools нет модуля
`XCTest`, а `Testing.framework` есть, но SwiftPM не знает путей до него. Обвязка их
подставляет. Обход через `unsafeFlags` однажды дал **ложно-зелёный результат**:
сборка проходила, тестов запускалось ноль, код выхода был нулевой.

**Предупреждения мерить только так:** `rm -rf .build && ./scripts/test.sh 2>&1 | grep -c "warning:"`.
Обычный `swift build` тестовый таргет не видит. Повторный запуск без чистки тоже
врёт: перекомпилировать нечего.

**Тест, написанный по факту существующего поведения, закрепляет и дефект.** Ревью
нашло три таких: тест **без единой проверки** (убери защиту из кода — он останется
зелёным); тест, закрепляющий «битый файл = пустые данные» как контракт; тест,
проходящий по случайной причине и создающий ложную уверенность в живучести. Тест
должен выражать требование, а не наблюдение. Пример правильного: вместо «сочетание
равно ⌘⇧V» — «сочетание по умолчанию **не равно** системной вставке без
форматирования».

**Одно и то же значение, считаемое в двух местах, — источник трёх дефектов.**
Раскладка панели считалась в одном месте, размер окна в другом, и никто не сверял их
вместе. Днём это починили на карточке; ревью нашло то же самое в двух других
состояниях. Правильный ответ — чистая функция от состояния, накрытая тестом.

**Кто создаёт возможность — тот её и подключает.** Плеер, календарь, погода и заряды
оказались написаны, покрыты тестами и не подключены ни к чему, потому что каждая
задача считала подключение чужой работой, а задачи «собрать всё вместе» в плане не
было вовсе. Теперь правило записано в план, и в брифах оно требуется явно.

**Константы из `Config` в задание агенту не попадают** — генератор вырезает только
раздел своей задачи. Значение надо дублировать в текст задачи, иначе исполнитель
придумает своё, и план с кодом разойдутся молча. Попались трижды.

**Инструментовка, встроенная в проверяемую цепочку, сама становится дефектом.**
Первый замер плеера дал ноль карточек, и это почти попало в отчёт как «правильное
поведение» — а на самом деле пробник подменял обработчик и координатор не получал
ничего. Слушать надо то, что подсистема отдаёт наружу, ничего не подменяя.

**Снимок экрана не показывает физическую челку.** Система отдаёт кадр вместе с
областью за вырезом, поэтому чёрная фигура выглядит на снимке отдельным
прямоугольником в строке меню. «Стык незаметен» проверяется только человеком.

**Работа исполнителей — только в отдельных воркри.** Двое агентов в общем дереве
привели к тому, что несохранённые правки одного молча откатились.

**Гасить приложение только по имени исполняемого файла.** Шаблон
`pkill -f "4elka.*/Chelka"` совпадает и с процессами компилятора — уже убивал сборку
соседнего агента.

**Не запускать много агентов «на всякий случай»:** лимит сессии общий. Первый запуск
трёх ревьюеров умер целиком, не начав работу.
